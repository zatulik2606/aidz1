# Шустрый Bot

Telegram-бот на базе LLM для первичного анализа аварийных событий в эксплуатации ИТ-продуктов.  
Бот помогает дежурному инженеру быстро классифицировать инцидент, оценить влияние, сформировать гипотезы причин и выбрать первые шаги локализации.

## Основные возможности

- Анализ описания аварии в роли инженера мониторинга
- Классификация инцидента по слою (сеть, приложение, инфраструктура, БД, внешние зависимости)
- Выдача вероятных первопричин с приоритизацией
- Рекомендации по первичным действиям (что проверить, какие логи/дашборды посмотреть)
- Поддержка контекста диалога в рамках чата
- Команда `/reset` для очистки контекста текущего инцидента
- Обработка ошибок LLM/API с fallback-ответом

## Технологический стек

- Python 3.12
- aiogram (Telegram Bot API, polling)
- OpenAI Python client + OpenRouter
- uv (управление зависимостями и запуск)
- Docker + Docker Compose
- Railway (облачный деплой)

## Установка и запуск

### 1) Подготовка окружения

```bash
cp .env.example .env
```

Заполните в `.env` обязательные переменные:

- `TELEGRAM_BOT_TOKEN`
- `LLM_PROVIDER` (по умолчанию `openrouter`)
- `LLM_BASE_URL` (по умолчанию `https://openrouter.ai/api/v1`)
- `LLM_API_KEY`
- `LLM_MODEL`
- `SYSTEM_PROMPT`

### 2) Локальный запуск (без Docker)

```bash
make install
make run
```

### 3) Локальный запуск в Docker

```bash
make docker-build
make run-docker
```

Остановить контейнер:

```bash
make docker-down
```

### 4) Деплой в Railway (кратко)

- Подключите репозиторий в Railway
- Убедитесь, что используется `Dockerfile` / `railway.toml`
- Добавьте переменные окружения из `.env.example`
- Для Railway указывайте внешние модели (через API, например OpenRouter), а не локальные `localhost`/Ollama-модели
- Выполните deploy и проверьте логи `Start polling`

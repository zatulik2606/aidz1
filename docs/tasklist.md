## Итерации

### Итерация 1 — Инфраструктура, конфиг, базовый бот
- [ ] Инициализировать проект через `uv` (`pyproject.toml`)
- [ ] Добавить зависимости: `aiogram`, `openai`, `python-dotenv`
- [ ] Создать структуру папок (`src/`, `tests/`)
- [ ] Создать `.env.example` с перечнем всех обязательных переменных
- [ ] Создать `Makefile` с командами `install`, `run`, `docker-build`, `run-docker`, `docker-down`
- [ ] Реализовать `src/config.py`: загрузка и валидация переменных из `.env`, fail fast при отсутствии обязательных
- [ ] Настроить логгирование через stdlib `logging` в `stdout`
- [ ] Реализовать `src/main.py` и `src/handlers.py`: запуск polling, обработчик `/start`

**Проверка:** Бот запускается через `make run` и отвечает на `/start` в Telegram.

---

### Итерация 2 — Интеграция с LLM (без истории)
- [ ] Реализовать `src/llm.py`: вызов LLM через `openai` client с поддержкой переключения провайдера
- [ ] Подключить LLM к обработчику сообщений: каждое новое сообщение отправляется в LLM с системным промптом

**Проверка:** Бот отвечает на любое сообщение через LLM, но не помнит предыдущих сообщений.

---

### Итерация 3 — История диалога
- [ ] Реализовать `src/dialog_store.py`: in-memory хранение истории по `chat_id`
- [ ] Передавать историю чата в запрос к LLM

**Проверка:** Бот ведёт осмысленный диалог с памятью контекста.

---

### Итерация 4 — Команда /reset
- [ ] Добавить обработчик `/reset` в `handlers.py`
- [ ] При вызове команды история текущего чата очищается

**Проверка:** После `/reset` бот не помнит предыдущих сообщений.

---

### Итерация 5 — Обработка ошибок
- [ ] Обработать ошибки LLM API и сети: fallback-сообщение пользователю
- [ ] Логировать причину ошибки на уровне `ERROR`

**Проверка:** При недоступном LLM API бот отвечает корректно, не падает.

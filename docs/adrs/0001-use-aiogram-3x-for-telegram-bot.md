# ADR 0001: Использовать aiogram 3.x как фреймворк Telegram-бота

- Статус: принято
- Дата: 2026-05-03

## Контекст

Проект реализует LLM-ассистента в формате Telegram-бота.  
Нам нужен надежный способ:

- получать и маршрутизировать входящие сообщения;
- обрабатывать команды, кнопки и события Telegram;
- управлять состоянием диалога пользователя;
- масштабировать код по мере роста сценариев бота.

Реализация этого слоя вручную через raw Telegram Bot API увеличит сложность, время разработки и риск ошибок.

## Решение

Использовать `aiogram 3.x` как основной фреймворк для Telegram-бота в проекте.

`aiogram 3.x` используется для:

- роутинга апдейтов и разделения логики по хендлерам;
- построения пошаговых сценариев (FSM/состояния);
- работы с middleware, фильтрами и зависимостями;
- унифицированного взаимодействия с Telegram Bot API.

## Почему это решение

- Ускоряет разработку: меньше инфраструктурного кода вокруг Telegram API.
- Делает код поддерживаемым: четкая структура роутеров и хендлеров.
- Упрощает расширение: новые команды и сценарии добавляются предсказуемо.
- Снижает риск регрессий: зрелая экосистема и понятные паттерны.

## Последствия

Положительные:

- Быстрый старт и удобная архитектура для роста функциональности.
- Меньше самописной обвязки вокруг Telegram-интеграции.

Негативные/ограничения:

- Появляется зависимость от API и подходов `aiogram 3.x`.
- Команде нужно придерживаться практик и структуры фреймворка.

## Альтернативы, которые рассматривались

1. Прямая работа с Telegram Bot API без фреймворка  
   Отклонено: выше порог сложности и поддержка обходится дороже.
2. Другой Python-фреймворк для Telegram-ботов  
   Не выбран: `aiogram 3.x` лучше соответствует async-подходу и удобен для модульной архитектуры проекта.
